# Antigravity 행동 규칙 (Rules)

## 코드 직접 수정 제한
- 파일을 직접 수정하는 도구(write_to_file, replace_file_content, multi_replace_file_content 등)를 사용하기 전에, 반드시 사용자에게 수정 계획을 먼저 설명하고 승인을 받아야 합니다.
- 사용자가 "코드를 수정해 줘", "적용해 줘" 등 명시적인 지시를 내리기 전에는 임의로 프로젝트 파일을 변경할 수 없습니다.
- 항상 수정할 내용을 코드 스니펫(Diff 또는 전체 코드)으로 대화창에 먼저 제안하고 의견을 구하세요.

## Pull Request 작성 기준
- PR 제목과 본문은 한국어로 작성합니다. 라이브러리명, 코드 식별자, 명령어처럼 번역하면 의미가 달라지는 기술 용어는 원문을 유지할 수 있습니다.
- PR 생성 전 head/base 브랜치와 변경 범위를 사용자에게 보고하고 승인을 받습니다.
- PR 본문은 최소한 `변경 목적`, `주요 변경`, `영향 범위`, `검증 결과`, `배포 후 확인` 항목을 포함합니다.
- 관련 이슈가 있다면 PR 본문에 연결하고, 호환성 변경이나 후속 작업이 있다면 명확히 표시합니다.
- 테스트를 실행하지 못했거나 일부 검증이 남았다면 완료된 것처럼 표현하지 않고 사유와 필요한 확인 방법을 적습니다.
- DB 스키마, 환경변수, Secret, 외부 서비스 설정이 변경되면 필요한 값과 적용 순서를 적되 실제 비밀값은 기록하지 않습니다.
- 로그, 스크린샷, 명령 출력에 토큰, 비밀번호, 개인정보 등 민감정보가 포함되지 않았는지 확인합니다.
- 하나의 PR에는 하나의 목적에 해당하는 변경만 포함하고, 관련 없는 리팩터링이나 문서 변경을 섞지 않습니다.
